8\. GLOBAL MOTION SYSTEM  
\--------------------------------------------------

Animation must have a purpose.

Every animation must answer:

"What does this movement explain?"

Create standardized motion tokens:

MICRO  
FAST  
STANDARD  
SLOW  
DRAMATIC

Use:

\- opacity  
\- transform  
\- clip-path  
\- scale  
\- subtle blur  
\- layout transitions

Avoid constant movement.

Avoid animations that continue forever without communicating state.

Avoid excessive parallax.

Avoid animation for decoration alone.

Respect:

prefers-reduced-motion

When reduced motion is enabled:

\- remove parallax  
\- remove large transitions  
\- replace animated diagrams with static states  
\- preserve all information

Motion should communicate:

\- progression  
\- transformation  
\- hierarchy  
\- cause and effect  
\- state change  
\- interaction

Never motion simply because it looks cool.

\--------------------------------------------------  
9\. PERFORMANCE  
\--------------------------------------------------

Performance is part of premium.

Target:

LCP \<= 2.5 seconds

INP \<= 200ms

CLS \<= 0.1

Measure at the 75th percentile.

Reference:

https://web.dev/articles/vitals

Core Web Vitals represent loading, responsiveness and visual stability.

Do not sacrifice performance for animation.

Protect:

\- initial JavaScript  
\- image sizes  
\- font loading  
\- animation workload  
\- layout stability  
\- hydration  
\- unnecessary dependencies  
\- third-party scripts

Use lazy loading where appropriate.

Avoid loading huge animation libraries when a small custom animation is enough.

Avoid unnecessarily large video assets.
